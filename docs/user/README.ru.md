# Karyora — Руководство пользователя

Это руководство описывает настольное приложение Karyora в том виде, в каком оно поставляется сегодня. Здесь указано только то, что продукт действительно делает; возможности, которых ещё нет, перечислены как ограничения и никогда не подаются как обещания. Это же руководство доступно в этом каталоге на 12 языках.

## 1. Что такое Karyora

- Karyora — настольное приложение с локальным приоритетом (local-first). Ваши пакеты знаний, задания и настройки хранятся на вашем собственном компьютере.
- Продукт работает без каких-либо облачных сервисов проекта. Единственный сетевой трафик, который он может создавать, — это трафик, инициированный вами: запросы к вашим ИИ-провайдерам, запрошенный вами импорт пакета знаний и — если вы его настроите — канал обновлений.
- Функции ИИ используют ваши собственные аккаунты провайдеров (BYOK — bring your own key). Вы настраиваете свои ключи API, и провайдер выставляет вам счёт напрямую. Karyora никогда не перепродаёт использование провайдеров и не выступает посредником в их оплате.

## 2. Сборки сообщества и официальные сборки

- Исходный код Karyora выпущен под лицензией Apache License 2.0. Вы можете использовать, изучать, изменять и распространять его на условиях этой лицензии, включая сборку самостоятельно.
- Публичный репозиторий — `https://github.com/qira-dev/karyora`. Каждый выпуск помечен тегом `v*`, и дерево исходников этого тега является исходным кодом выпуска.
- «Официальной» является сборка, выполненная собственным конвейером сборки проекта на помеченной тегом ревизии с записанными доказательствами. Официальные и общинные сборки имеют одинаковые возможности; разница — в том, кто собрал артефакт и кто за него отвечает, а не в том, что артефакт умеет.
- В v1 пока нет официальной страницы загрузок и официального канала обновлений. Пока они не опубликованы, Karyora можно получить из публичного репозитория и собрать из исходного кода.

## 3. Поддерживаемые платформы (v1)

| ОС | CPU | Нижняя граница |
|---|---|---|
| Windows 11 | x86_64 | Windows 11, 23H2 или новее |
| Windows 11 | ARM64 | Windows 11 для ARM |
| macOS | x86_64 | macOS 15 (Sequoia) или новее |
| macOS | ARM64 | macOS 15 (Sequoia) или новее, Apple Silicon |
| Linux | x86_64 | glibc 2.34 или новее; Ubuntu LTS 22.04/24.04, Debian 12+, RHEL 9+ |
| Linux | ARM64 | glibc 2.34 или новее; те же семейства дистрибутивов |

Явно не поддерживается в v1: Windows 10; macOS 14 и старше; дистрибутивы на musl, такие как Alpine; любая комбинация, не указанная выше. Поддержка следует за окном безопасности самого поставщика и перепроверяется при каждом выпуске.

## 4. Пакеты и как их проверять

- Набор создаваемых пакетов: Windows MSI, macOS pkg, Linux deb, Linux rpm и переносимый архив Linux — по одному артефакту на каждую поддерживаемую архитектуру CPU.
- Каждый пакет создаётся вместе с манифестом `SHA256SUMS`, а также записями SBOM и провенанса для артефакта. Чтобы проверить пакет: вычислите sha256-дайджест загруженного файла и сравните его со значением из манифеста. Если дайджест не совпадает, не устанавливайте пакет.
- В v1 пакеты по замыслу не имеют цифровой подписи. Шаги проверки подписи на уровне платформы (проверки подписи ОС, ключи репозиториев) будут задокументированы вместе с первым подписанным выпуском. До этого момента доступная вам проверка — это сравнение дайджестов, описанное выше.
- Файлы `LICENSE` и `NOTICE`, содержащие лицензию проекта и указания авторства третьих компонентов, являются частью репозитория исходного кода.

## 5. Обновления

- В Karyora есть механизм обновления, и в v1 он поставляется отключённым по умолчанию. Канал обновлений не настроен, поэтому проверка обновлений выдаёт типизированный отказ, в котором сказано, что конечная точка не настроена. Это сделано намеренно: официальный канал обновлений будет включён только после его публикации.
- До тех пор обновление означает установку нового пакета поверх старого. При обновлении ваши данные сохраняются (см. раздел 6).

## 6. Ваши данные

- Все данные продукта находятся на вашем компьютере. Каталог данных по умолчанию: `%APPDATA%\Karyora\data` в Windows, `~/Library/Application Support/Karyora/data` в macOS и `~/.local/share/karyora/data` в Linux (учитывается настройка XDG `XDG_DATA_HOME`). Другое расположение можно задать флагом `--data-dir`.
- Продукт не выполняет резервное копирование по расписанию. Чтобы сделать резервную копию, остановите продукт и скопируйте каталог данных. Восстановление — это вернуть скопированный каталог на место. Облачной резервной копии нет.
- Удаление программы или обновление не стирает ваши данные. Удаление данных — это отдельное, явное действие, которое вы выполняете сами.
- Данные в покое не шифруются. Защищайте каталог данных своими средствами, например шифрованием всего диска. Это известное ограничение, заявленное прямо.
- Учётные данные провайдеров (ваши ключи API) хранятся только в связке ключей вашей операционной системы. Они никогда не записываются в файлы, журналы или содержимое запросов.

## 7. Конфиденциальность

- В продукте нет телеметрии: на серверы проекта ничего не отправляется.
- Диагностика создаётся локально и по умолчанию остаётся конфиденциальной; решаете ли вы, что-либо вообще покидает ваш компьютер.

## 8. Известные ограничения v1

- Выполнение сторонних плагинов отключено.
- Командный и удалённый режим недоступен.
- Перенос активного задания с одной машины на другую не поддерживается.
- Синхронизация переносимых пакетов знаний недоступна.
- Группировка «Work» отсутствует.
- Платных подписок и прав (entitlement) нет: покупать нечего, платных тарифов нет.
- Никаких числовых обещаний о производительности не даётся.
- Данные в покое не шифруются (см. раздел 6).
- Официальной страницы загрузок и канала обновлений пока нет (см. разделы 2 и 5).

## 9. Лицензия

- Karyora выпускается под лицензией Apache License 2.0. Полный текст лицензии — в файле `LICENSE`, указания авторства третьих компонентов — в файле `NOTICE`; оба файла находятся в репозитории исходного кода.
- Самостоятельная сборка Karyora, создание форков и распространение на условиях лицензии сохраняют все права, которые предоставляет лицензия. Это право ни от чего не зависит, потому что покупать нечего.

## 10. Справочник по командной строке

Инструмент командной строки — `uawp`.

| Команда | Что делает |
|---|---|
| `uawp start` | Запускает локальную службу. Второй запуск на том же каталоге данных отклоняется, пока один уже работает. |
| `uawp stop` | Останавливает службу с ограниченным, корректным завершением. |
| `uawp status` | Сообщает, работает ли служба. |
| `uawp doctor` | Выполняет локальные проверки состояния и диагностику. |
| `uawp update check` / `uawp update apply` / `uawp update status` | Проверяет, применяет или сообщает об обновлениях. В v1, пока канал не настроен, check и apply завершаются типизированным отказом с указанием, что конечная точка не настроена; `status` сообщает состояние обновлений. |
| `uawp job submit` / `uawp job status` / `uawp job events` | Отправляет постоянное задание, сообщает его статус или следит за его событиями. |
| `uawp credential store --provider <id> [--name api-key]` | Сохраняет ключ API провайдера в связке ключей ОС. |
| `uawp credential status` | Сообщает только о наличии учётных данных — никогда об их значении. |
| `uawp credential remove` | Удаляет сохранённые учётные данные. |
| `uawp version` / `uawp help` | Печатает версию или справку. |

Само по себе сохранение учётных данных ничего не открывает: реальный вызов провайдера всё равно должен пройти правила обработки данных, установленные продуктом для этого провайдера.
