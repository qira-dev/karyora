# Karyora — 用户指南

本指南介绍 Karyora 桌面应用程序的当前交付状态。它只陈述产品实际具备的功能；尚不存在的能力一律列为限制，绝不作为承诺。同一指南在本目录下提供 12 种语言版本。

## 1. Karyora 是什么

- Karyora 是一个以本地优先为原则的桌面应用程序。你的知识包、任务和设置都存储在你自己的计算机上。
- 本产品运行不依赖本项目的任何云服务。它能够产生的网络流量只有你主动发起的部分：发给你 AI 提供商的请求、你请求的知识包导入，以及（在你进行配置时）更新通道。
- AI 功能使用你自己的提供商账户（自带密钥，BYOK）。你配置自己的 API 密钥，由提供商直接向你收费。Karyora 从不转售提供商的使用量，也从不充当提供商付款的中介。

## 2. 社区版本与官方版本

- Karyora 的源代码以 Apache License 2.0 发布。你可以在该许可下使用、研究、修改和再分发源代码，包括自行构建。
- 公共仓库为 `https://github.com/qira-dev/karyora`。每个版本都由一个 `v*` 标签标记，该标签所指的源码树就是该版本的源代码。
- "官方"版本是指由项目自己的构建流水线在某个带标签的修订版本上构建、并带有可查证证据的版本。官方构建与社区构建功能完全相同；区别只在于产物由谁构建、由谁负责，而绝不是产物能做什么。
- 在 v1 中，官方下载页面和官方更新通道尚不存在。在它们发布之前，你可以从公共仓库获取 Karyora 并从源代码自行构建。

## 3. 支持的平台（v1）

| 操作系统 | CPU | 最低版本要求 |
|---|---|---|
| Windows 11 | x86_64 | Windows 11 23H2 或更新 |
| Windows 11 | ARM64 | Windows on ARM 版 Windows 11 |
| macOS | x86_64 | macOS 15 (Sequoia) 或更新 |
| macOS | ARM64 | macOS 15 (Sequoia) 或更新，Apple Silicon |
| Linux | x86_64 | glibc 2.34 或更新；Ubuntu LTS 22.04/24.04、Debian 12+、RHEL 9+ |
| Linux | ARM64 | glibc 2.34 或更新；同样的发行版家族 |

v1 明确不支持：Windows 10；macOS 14 及更早版本；musl 系发行版（如 Alpine）；上表未列出的所有其他组合。支持状态跟随各厂商自身的安全支持窗口，并在每次发布时重新核对。

## 4. 软件包及其校验方法

- 已产出的软件包集合为：Windows MSI、macOS pkg、Linux deb、Linux rpm，以及一个 Linux 便携归档 —— 每个受支持的 CPU 架构各一个产物。
- 每个软件包都随附 `SHA256SUMS` 清单以及该产物的 SBOM 与来源（provenance）记录。校验软件包的方法是：计算你下载文件的 sha256 摘要，并与清单中的条目比对。如果摘要不一致，请不要安装该软件包。
- v1 的软件包按设计不进行数字签名。平台级的签名校验步骤（操作系统级签名检查、仓库密钥）将随第一个带签名的版本一同提供文档。在此之前，你可以执行的校验就是上述摘要比对。
- 载有项目许可证与第三方声明的 `LICENSE` 和 `NOTICE` 文件是源代码仓库的一部分。

## 5. 更新

- Karyora 内含更新机制，并且在 v1 中默认处于禁用状态。由于没有配置任何更新通道，更新检查会报告一个明确指出"未配置端点"的类型化拒绝。这是有意为之：官方更新通道只有在其正式发布后才会开启。
- 在此之前，升级意味着用较新的软件包覆盖安装旧版本。升级会保留你的数据（见第 6 节）。

## 6. 你的数据

- 产品的全部数据都存储在你自己的机器上。默认数据目录为：Windows 上的 `%APPDATA%\Karyora\data`、macOS 上的 `~/Library/Application Support/Karyora/data`、Linux 上的 `~/.local/share/karyora/data`（遵循 XDG 的 `XDG_DATA_HOME` 设置）。你可以用 `--data-dir` 标志选择其他位置。
- 本产品不执行定时备份。要备份，请先停止产品，然后复制数据目录。恢复就是把复制的目录放回原处。没有云备份。
- 卸载或升级不会删除你的数据。删除数据是一个独立的、需要你自己执行的操作。
- 静态数据未加密。请用你自己的手段（如全盘加密）保护数据目录。这是一个明确陈述的已知限制。
- 提供商凭据（你的 API 密钥）只存储在操作系统的钥匙串中。它们绝不会写入文件、日志或提示内容。

## 7. 隐私

- 本产品不包含遥测：不会有任何数据发送到本项目的服务器。
- 诊断信息在本地生成，默认保持隐私安全；是否有任何内容离开你的机器由你决定。

## 8. v1 的已知限制

- 第三方插件执行处于禁用状态。
- 团队与远程操作不可用。
- 不支持把正在运行的任务从一台机器转移到另一台机器。
- 便携知识包同步不可用。
- "Work"分组功能不存在。
- 没有付费订阅，也没有授权（entitlement）：无物可买，没有付费档位。
- 不做任何具体的性能数字承诺。
- 静态数据未加密（见第 6 节）。
- 官方下载页面与官方更新通道尚不存在（见第 2 与第 5 节）。

## 10. 命令行参考

命令行工具是 `uawp`。

| 命令 | 作用 |
|---|---|
| `uawp start` | 启动本地服务。同一数据目录上已有实例在运行时，再次启动会被拒绝。 |
| `uawp stop` | 以有界的、平稳的方式停止服务。 |
| `uawp status` | 报告服务是否正在运行。 |
| `uawp doctor` | 执行本地健康与诊断检查。 |
| `uawp update check` / `uawp update apply` / `uawp update status` | 检查、应用或报告更新。在 v1 中，由于未配置通道，check 与 apply 会以类型化拒绝（指出未配置端点）结束；`status` 报告更新状态。 |
| `uawp job submit` / `uawp job status` / `uawp job events` | 提交持久化任务、报告其状态或跟踪其事件。 |
| `uawp credential store --provider <id> [--name api-key]` | 把你的提供商 API 密钥存入操作系统钥匙串。 |
| `uawp credential status` | 报告凭据是否存在 —— 绝不显示其值。 |
| `uawp credential remove` | 删除已存储的凭据。 |
| `uawp version` / `uawp help` | 打印版本号或帮助信息。 |

仅存储凭据本身不会开启任何能力：实际的提供商调用仍必须通过产品针对该提供商的数据处理规则。
