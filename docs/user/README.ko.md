# Karyora — 사용자 안내서

이 안내서는 현재 출하된 Karyora 데스크톱 애플리케이션을 설명합니다. 제품이 실제로 하는 일만을 서술하며, 아직 존재하지 않는 기능은 반드시 제한 사항으로 나열할 뿐 약속으로 제시하지 않습니다. 같은 안내서가 이 폴더에 12개 언어로 제공됩니다.

## 1. Karyora란

- Karyora는 로컬 우선(local-first) 데스크톱 애플리케이션입니다. 지식 팩, 작업(job), 설정은 모두 사용자 자신의 머신에 저장됩니다.
- 이 제품은 프로젝트가 제공하는 클라우드 서비스 없이 동작합니다. 발생할 수 있는 네트워크 트래픽은 사용자가 시작한 것뿐입니다. 즉, AI 공급자에게 보내는 요청, 사용자가 요청한 지식 팩 가져오기, 그리고 (설정한 경우) 업데이트 채널입니다.
- AI 기능은 사용자 자신의 공급자 계정을 사용합니다(Bring Your Own Key, BYOK). 사용자가 직접 API 키를 구성하며, 비용은 공급자가 직접 청구합니다. Karyora는 공급자 사용량을 재판매하지 않고 공급자 결제의 중개자로 동작하지 않습니다.

## 2. 커뮤니티 빌드와 공식 빌드

- Karyora의 소스 코드는 Apache License 2.0으로 공개됩니다. 이 라이선스에 따라 사용, 연구, 수정, 재배포(직접 빌드 포함)를 할 수 있습니다.
- 공개 저장소는 `https://github.com/qira-dev/karyora`입니다. 각 릴리스는 `v*` 태그로 표시되며, 그 태그의 소스 트리가 해당 릴리스의 소스입니다.
- "공식" 릴리스란 프로젝트 자체 빌드 파이프라인이 태그가 붙은 리비전에서 기록된 증거와 함께 빌드한 것을 말합니다. 공식 빌드와 커뮤니티 빌드의 기능은 동일합니다. 차이는 아티팩트를 누가 빌드하고 누가 책임지는가에 있을 뿐, 아티팩트가 무엇을 할 수 있는가에 있지 않습니다.
- v1에는 공식 다운로드 페이지와 공식 업데이트 채널이 아직 없습니다. 공개되기 전까지는 공개 저장소에서 Karyora를 가져와 소스에서 직접 빌드할 수 있습니다.

## 3. 지원 플랫폼(v1)

| OS | CPU | 하한 |
|---|---|---|
| Windows 11 | x86_64 | Windows 11 23H2 이상 |
| Windows 11 | ARM64 | ARM용 Windows 11 |
| macOS | x86_64 | macOS 15 (Sequoia) 이상 |
| macOS | ARM64 | macOS 15 (Sequoia) 이상, Apple Silicon |
| Linux | x86_64 | glibc 2.34 이상. Ubuntu LTS 22.04/24.04, Debian 12+, RHEL 9+ |
| Linux | ARM64 | glibc 2.34 이상. 동일한 배포판 계열 |

v1에서 명시적으로 지원하지 않음: Windows 10, macOS 14 이하, Alpine 같은 musl 기반 배포판, 위에 나열되지 않은 모든 조합. 지원 여부는 각 공급사의 보안 지원 기간을 따르며 릴리스마다 다시 확인합니다.

## 4. 패키지와 검증 방법

- 생성되는 패키지는 다음과 같습니다. Windows MSI, macOS pkg, Linux deb, Linux rpm, 그리고 Linux 포터블 아카이브 — 지원되는 각 CPU 아키텍처마다 하나의 아티팩트.
- 모든 패키지에는 `SHA256SUMS` 매니페스트와 아티팩트별 SBOM 및 출처(provenance) 기록이 함께 만들어집니다. 패키지를 검증하려면: 내려받은 파일의 sha256 다이제스트를 계산해 매니페스트 항목과 비교하십시오. 다이제스트가 일치하지 않으면 그 패키지를 설치하지 마십시오.
- v1 패키지는 설계상 디지털 서명이 없습니다. 플랫폼 서명 검증 절차(OS 수준 서명 확인, 저장소 키)는 첫 서명 릴리스와 함께 문서화됩니다. 그 전까지 사용자가 할 수 있는 검증은 위의 다이제스트 비교입니다.
- 프로젝트 라이선스와 서드파티 표기를 담은 `LICENSE` 및 `NOTICE` 파일은 소스 저장소의 일부입니다.

## 5. 업데이트

- Karyora에는 업데이트 메커니즘이 포함되어 있으며, v1에서는 기본적으로 비활성화된 상태로 출하됩니다. 업데이트 채널이 구성되어 있지 않기 때문에, 업데이트 확인은 "엔드포인트가 구성되지 않았다"고 밝히는 형식화된 거절을 보고합니다. 이는 의도된 동작입니다. 공식 업데이트 채널은 공개된 이후에만 켜집니다.
- 그 전까지 업그레이드는 더 새 패키지를 기존 패키지 위에 설치하는 것을 의미합니다. 업그레이드 과정에서 데이터는 보존됩니다(6절 참조).

## 6. 사용자 데이터

- 제품의 모든 데이터는 사용자의 머신에 있습니다. 기본 데이터 디렉터리는 Windows에서 `%APPDATA%\Karyora\data`, macOS에서 `~/Library/Application Support/Karyora/data`, Linux에서 `~/.local/share/karyora/data`입니다(XDG `XDG_DATA_HOME` 설정을 따릅니다). `--data-dir` 플래그로 다른 위치를 지정할 수 있습니다.
- 제품은 예약 백업을 수행하지 않습니다. 백업하려면 제품을 중지하고 데이터 디렉터리를 복사하십시오. 복원이란 복사해 둔 디렉터리를 원래 자리에 되돌려 놓는 것입니다. 클라우드 백업은 없습니다.
- 제거하거나 업그레이드해도 데이터는 삭제되지 않습니다. 데이터 삭제는 사용자가 직접 수행하는 별도의 명시적 행위입니다.
- 저장 데이터는 암호화되어 있지 않습니다. 전체 디스크 암호화 같은 사용자 자신의 수단으로 데이터 디렉터리를 보호하십시오. 이는 분명히 밝힌 알려진 제한입니다.
- 공급자 자격 증명(사용자의 API 키)은 운영 체제 키체인에만 저장됩니다. 파일, 로그, 프롬프트 내용에 기록되는 일은 없습니다.

## 7. 개인정보

- 이 제품에는 텔레메트리가 없습니다. 프로젝트 서버로 아무것도 보내지 않습니다.
- 진단 정보는 로컬에서 생성되며 기본적으로 프라이버시를 지킵니다. 사용자 머신 밖으로 무엇을 내보낼지는 사용자가 결정합니다.

## 8. v1의 알려진 제한

- 서드파티 플러그인 실행은 비활성화되어 있습니다.
- 팀 및 원격 운영은 사용할 수 없습니다.
- 실행 중인 작업을 다른 머신으로 옮기는 것은 지원되지 않습니다.
- 포터블 지식 팩 동기화는 사용할 수 없습니다.
- "Work" 그룹화 기능은 존재하지 않습니다.
- 유료 구독이나 자격(entitlement)이 없습니다. 살 수 있는 것이 없고 유료 등급도 없습니다.
- 수치로 된 성능 약속은 하지 않습니다.
- 저장 데이터는 암호화되어 있지 않습니다(6절 참조).
- 공식 다운로드 페이지와 공식 업데이트 채널이 아직 없습니다(2절과 5절 참조).

## 9. 라이선스

- Karyora는 Apache License 2.0으로 공개됩니다. 전체 라이선스 문서는 소스 저장소의 `LICENSE` 파일에, 서드파티 표기는 `NOTICE` 파일에 있습니다.
- 직접 빌드하거나, 포크하거나, 라이선스에 따라 재배포해도 라이선스가 부여하는 모든 권리는 유지됩니다. 이 권리는 구매와 무관합니다. 애초에 살 수 있는 것이 없기 때문입니다.

## 10. 명령줄 참조

명령줄 도구는 `uawp`입니다.

| 명령 | 하는 일 |
|---|---|
| `uawp start` | 로컬 서비스를 시작합니다. 같은 데이터 디렉터리에서 이미 실행 중인 인스턴스가 있으면 두 번째 시작은 거절됩니다. |
| `uawp stop` | 상한이 있는 정상 종료 절차로 서비스를 중지합니다. |
| `uawp status` | 서비스 실행 여부를 보고합니다. |
| `uawp doctor` | 로컬 상태 점검과 진단을 수행합니다. |
| `uawp update check` / `uawp update apply` / `uawp update status` | 업데이트를 확인·적용·보고합니다. v1에서는 채널이 구성되지 않아 check와 apply는 "엔드포인트가 구성되지 않았다"고 밝히는 형식화된 거절로 끝나며, `status`는 업데이트 상태를 보고합니다. |
| `uawp job submit` / `uawp job status` / `uawp job events` | 영속 작업을 제출하거나, 상태를 보고하거나, 이벤트를 추적합니다. |
| `uawp credential store --provider <id> [--name api-key]` | 공급자 API 키를 OS 키체인에 저장합니다. |
| `uawp credential status` | 자격 증명의 존재 여부만 보고합니다 — 값은 절대 표시하지 않습니다. |
| `uawp credential remove` | 저장된 자격 증명을 제거합니다. |
| `uawp version` / `uawp help` | 버전 또는 도움말을 출력합니다. |

자격 증명을 저장하는 것만으로는 아무것도 열리지 않습니다. 실제 공급자 호출은 그 공급자에 대한 제품의 데이터 처리 규칙을 통과해야 합니다.
