# Karyora — ユーザーガイド

このガイドは、現在出荷されている Karyora デスクトップアプリケーションについて説明します。実際に製品が持つ機能だけを記述し、まだ存在しない能力は必ず「制限」として列挙し、決して約束としては述べません。同じガイドは、このフォルダー内に 12 言語で用意されています。

## 1. Karyora とは

- Karyora はローカルファーストのデスクトップアプリケーションです。ナレッジパック・ジョブ・設定は、あなた自身のマシンに保存されます。
- 本製品の動作に、このプロジェクト提供のクラウドサービスは一切必要ありません。発生しうるネットワーク通信は、あなたが開始したものだけです。具体的には、AI プロバイダーへのリクエスト、あなたが依頼したナレッジパックのインポート、そして（設定した場合の）更新チャンネルです。
- AI 機能はあなた自身のプロバイダーアカウントを使用します（BYOK — Bring Your Own Key）。API キーはあなた自身のもので、利用料はプロバイダーが直接請求します。Karyora がプロバイダーの利用量を再販売することや、支払いの仲介者になることはありません。

## 2. コミュニティ版と公式版

- Karyora のソースコードは Apache License 2.0 の下で公開されています。このライセンスの条件下で、使用・研究・改変・再配布（自分でのビルドを含む）が可能です。
- 公開リポジトリーは `https://github.com/qira-dev/karyora` です。各リリースは `v*` タグで示され、そのタグのソースツリーがそのリリースのソースです。
- 「公式」リリースとは、プロジェクト自身のビルドパイプラインがタグ付きリビジョンで、記録された証拠とともにビルドしたものを指します。公式ビルドとコミュニティビルドの機能は同一です。違いはアーティファクトを誰がビルドし誰が責任を持つかにのみあり、アーティファクトが何をしてくれるかではありません。
- v1 の時点では、公式ダウンロードページも公式更新チャンネルも存在しません。公開されるまでの間、Karyora は公開リポジトリーから取得し、ソースからビルドできます。

## 3. 対応プラットフォーム（v1）

| OS | CPU | 下限 |
|---|---|---|
| Windows 11 | x86_64 | Windows 11 23H2 以降 |
| Windows 11 | ARM64 | ARM 版 Windows 11 |
| macOS | x86_64 | macOS 15 (Sequoia) 以降 |
| macOS | ARM64 | macOS 15 (Sequoia) 以降、Apple Silicon |
| Linux | x86_64 | glibc 2.34 以降。Ubuntu LTS 22.04/24.04、Debian 12+、RHEL 9+ |
| Linux | ARM64 | glibc 2.34 以降。同じディストリビューション群 |

v1 で明示的に非対応: Windows 10、macOS 14 以前、Alpine などの musl 系ディストリビューション、上記にないすべての組み合わせ。対応状況は各ベンダーのセキュリティサポート期間に従い、リリースごとに再確認します。

## 4. パッケージと検証方法

- 生成されるパッケージは次のとおりです: Windows MSI、macOS pkg、Linux deb、Linux rpm、および Linux ポータブルアーカイブ — 対応する各 CPU アーキテクチャーごとに 1 つのアーティファクト。
- すべてのパッケージには `SHA256SUMS` マニフェストと、アーティファクトごとの SBOM およびトレーサビリティ（provenance）記録が伴います。検証方法: ダウンロードしたファイルの sha256 ダイジェストを計算し、マニフェストのエントリーと比較してください。ダイジェストが一致しない場合は、そのパッケージをインストールしないでください。
- パッケージは設計上、v1 ではデジタル署名されていません。プラットフォームの署名検証手順（OS レベルの署名チェック、リポジトリーキー）は、最初の署名付きリリースとともに文書化されます。それまでは、上記のダイジェスト比較があなたにできる検証です。
- プロジェクトのライセンスおよびサードパーティー表示を載せた `LICENSE` と `NOTICE` の各ファイルは、ソースリポジトリーの一部です。

## 5. 更新

- Karyora には更新機構が含まれていますが、v1 では既定で無効のまま出荷されます。更新チャンネルが設定されていないため、更新の確認は「エンドポイントが設定されていない」ことを示す型付きの拒否を返します。これは意図的な動作です。公式更新チャンネルは、公開されたときにだけ有効になります。
- それまでは、新しいパッケージを古いパッケージの上にインストールするのがアップグレードです。アップグレードをまたいでデータは保持されます（第 6 節を参照）。

## 6. あなたのデータ

- 製品のデータはすべてあなたのマシン上にあります。既定のデータディレクトリーは、Windows では `%APPDATA%\Karyora\data`、macOS では `~/Library/Application Support/Karyora/data`、Linux では `~/.local/share/karyora/data` です（XDG の `XDG_DATA_HOME` 設定に従います）。`--data-dir` フラグで別の場所を選択できます。
- 製品は定期的なバックアップを行いません。バックアップするには、製品を停止してデータディレクトリーをコピーしてください。復元とは、コピーしたディレクトリーを元の場所に戻すことです。クラウドバックアップはありません。
- アンインストールやアップグレードでデータが削除されることはありません。データの削除は、あなた自身が行う独立した明示的な操作です。
- 保存データは暗号化されていません。フルディスク暗号化など、あなた自身の手段でデータディレクトリーを保護してください。これは明示的に記載された既知の制限です。
- プロバイダー資格情報（あなたの API キー）は、OS のキーチェーンにだけ保存されます。ファイル・ログ・プロンプトの内容に書き込まれることはありません。

## 7. プライバシー

- 本製品にテレメトリーは含まれません: プロジェクトのサーバーに何かを送ることはありません。
- 診断情報はローカルで生成され、既定ではプライバシーを保ちます。あなたのマシンから何かを出すかどうかは、あなたが制御します。

## 8. v1 の既知の制限

- サードパーティープラグインの実行は無効です。
- チームおよびリモート操作は利用できません。
- 実行中のジョブを別のマシンへ移すことはできません。
- ポータブルナレッジパックの同期は利用できません。
- 「Work」グルーピング機能は存在しません。
- 有料サブスクリプションやエンタイトルメントはありません: 購入できるものは何もなく、有料ティアもありません。
- 数値による性能の約束は一切していません。
- 保存データは暗号化されていません（第 6 節を参照）。
- 公式ダウンロードページと公式更新チャンネルはまだありません（第 2 節と第 5 節を参照）。

## 9. ライセンス

## 10. コマンドラインリファレンス

コマンドラインツールは `uawp` です。

| コマンド | 説明 |
|---|---|
| `uawp start` | ローカルサービスを開始します。同じデータディレクトリーで実行中のインスタンスがある場合、2 つ目の start は拒否されます。 |
| `uawp stop` | 上限付きの穏当なシャットダウンでサービスを停止します。 |
| `uawp status` | サービスが実行中かどうかを報告します。 |
| `uawp doctor` | ローカルのヘルスチェックと診断を実行します。 |
| `uawp update check` / `uawp update apply` / `uawp update status` | 更新の確認・適用・状態報告。v1 ではチャンネル未設定のため、check と apply は「エンドポイントが設定されていない」ことを示す型付きの拒否で終わり、`status` が更新状態を報告します。 |
| `uawp job submit` / `uawp job status` / `uawp job events` | 永続ジョブの投入、状態の報告、イベントの追跡。 |
| `uawp credential store --provider <id> [--name api-key]` | プロバイダーの API キーを OS のキーチェーンに保存します。 |
| `uawp credential status` | 資格情報の有無だけを報告します — 値そのものは決して表示しません。 |
| `uawp credential remove` | 保存済みの資格情報を削除します。 |
| `uawp version` / `uawp help` | バージョンまたはヘルプを表示します。 |

資格情報を保存しただけでは何も開かれません: 実際のプロバイダー呼び出しは、そのプロバイダーに対する製品のデータ取り扱い規則に合格しなければなりません。
